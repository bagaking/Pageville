## 北极星目标

让 Agent 与人在**本地**共享同一个可寻址的页面世界：一条命令把静态目录发布成
不可变快照，人在浏览器里看到的那一版，Agent 能精确指名、并把反馈写回同一版本。

判据（三者缺一不可）：

1. **可指名**：任何一次人看到的页面，都有一个永不漂移的 URL（`/{page}/{snapshot_id}/`）。
2. **可回流**：页面产生的事件带着快照版本写回，Agent 读到的事件能对上它当时看到的那一版。
3. **零仪式**：`publish` 一条命令完成一切，不需要先起服务、不需要配置文件。

## 关键分析

**为什么不用 `python -m http.server`**：没有版本、没有事件回流、没有稳定 URL。
人给反馈时说"那个按钮"，Agent 无法知道是哪一版的按钮——这正是 HITL 循环里最
昂贵的失真。

**为什么不用 Vercel/Netlify 之类**：v0 的场景是本机开发与受控预览，上传公网既慢
又有泄露风险，且离线不可用。

**为什么是单二进制**：见 PRD §6（O1 一体化 Rust daemon）。补充一条 PRD 未写的
理由——CLI 与 daemon 同一个二进制，版本天然不会错配。

## 技术选型与依赖

| 选型 | 理由 |
| --- | --- |
| axum 0.7 + tokio | 已在生态主流；中间件模型足够表达 Host/Origin 守卫 |
| rusqlite 0.31（bundled, WAL） | 免外部依赖；WAL 让读不阻塞写；事务保证 latest 原子切换 |
| blake3 | CAS 内容寻址，快且无碰撞顾虑 |
| reqwest（rustls） | CLI 复用同一套 HTTP 协议；rustls 免 OpenSSL 系统依赖 |

**许可证决策**：MIT。`cargo tree` 核查全部传递依赖为 MIT / Apache-2.0 / ISC /
BSD / CC0 等宽松协议，无 GPL/AGPL 传染项，MIT 相容。三处声明（`Cargo.toml`、
`package.json`、`LICENSE`）由 `scripts/npm/check.js` 强制一致。
