## 修复清单

### F-1 路径穿越校验误伤合法文件名（中）

`contains("..")` 是**子串**判断，而意图是**路径分量**判断。任何名字里带 `..`
的合法文件（`data..old.json`、`app.2..1.js`、`..lead`）都会让**整个快照**
发布失败，报错还是误导性的 `invalid path`。

修法是抽出共享的 `safe_rel_path()`，按 `/` 分段拒绝 `..` / `.` / 空段 / 反斜杠，
两个调用点（`api_publish` 与 `serve_page`）统一走它 —— 一处守卫而非两处补丁。

### F-2 `PAGEVILLE_PORT=0` 无限挂起并泄漏孤儿进程（中）

`0` 能通过 `parse()`，但对 OS 意味着"随便挑个空闲端口"：子进程绑到随机端口，
父进程却永远探测 `:0`。5 秒 spawn 循环结束后，父进程卡在对**仍然存活**的子进程
stderr 的阻塞 `read_to_string` 上 —— **无限挂起**，且每次调用泄漏一个孤儿 daemon。

两处根因分别修：
1. `port()` 用 `.filter(|p| *p != 0)` 把 0 视作未设置（6 个调用点共享此收口）。
2. `child_stderr_hint` 在读管道前先确认子进程已退出，未退出则先 kill 再读 ——
   这条**不止修 port 0**：任何"子进程活着但不可达"的场景原本都会挂。

### F-3 并发发布相同内容时虚假 500（低-中）

**这是我在 M01_S01.002 修 CAS 截断时自己引入的。** 临时文件名用了
`.{hash}.{pid}.tmp`，注释还写着"pid 防止并发互相覆盖"——但并发发布是**同一个
daemon 进程内的多个线程**，pid 相同，临时路径因此冲突：赢家 rename 走了共享
临时文件，输家的 rename 撞 `ENOENT` → 500。60 线程压测约 3% 失败。

改为 `AtomicU64` 每次调用自增的后缀。压测从 ~3% 失败变为 **60/60 全部成功**。

## 附带修复（我自己引入的回归）

- 加了 `safe_rel_path` 后，`/page/sub/` 这类目录式 URL 的**尾部空分量**被当成
  非法路径，`t012` 立刻变红（400 而非 404）。修法：尾斜杠先补 `index.html`
  再校验。**这正是回归测试该起的作用** —— 它在我提交前就抓住了。

## 经验沉淀

- **连续三轮都在自己的修复里发现新缺陷**（O-002 → O-005 → F-3）。F-3 尤其
  典型：注释信誓旦旦说"pid 防冲突"，而真实并发模型是**单进程多线程**。
  → 新增 [`OPINIONS_001`](OPINIONS_001.quality_bar.md) O-008。
- 测量本身也会骗人：`cmd | tail` 之后读 `$?` 拿到的是 `tail` 的退出码，一度让我
  误以为套件"打印了 FAIL 却退出 0"。**验证退出码必须不经管道。**
  → O-009。
