# M01_S01.001.FIX — 安全加固与虚假验收修复

> meta：记录审查后第一轮修复（P0 安全 + P1 正确性 + 工程基建）。
> 触发：对 v0 的系统质量审查发现 33 项确认问题。
> 状态：**已完成并验收**。

## 背景

一次多维度对抗式审查（55 项候选 → 33 项确认、22 项被驳回）暴露两类问题：

1. **浏览器可达面无防护** —— daemon 监听回环即被误认为无攻击面（见
   [`OPINIONS_001`](OPINIONS_001.quality_bar.md) O-007）。
2. **验收套件存在空断言** —— 部分切片必然通过（O-001）。

## OKR

- **O**：让 v0 的安全边界与验收信号都真实可信。
- **KR1**：浏览器发起的攻击（rebinding / 跨源写 / MIME 嗅探）全部被拒 —— 达成。
- **KR2**：发布路径不可能外泄链接目标 —— 达成。
- **KR3**：每条验收断言在对应逻辑损坏时会红 —— 达成（空断言已重写）。

## 偏差记录

计划内。但过程中**我自己引入了两个缺陷**，均在同轮发现并修复：
1. `t012` 的 `--until` 边界用 shell 做小时加法，跨午夜未进位日期，断言写反。
   改用 python3 计算，并加"边界失效自曝"防呆断言。
2. `t008` 失败时不点名切片。已改为打印切片名与退出码，并用故意失败的 canary
   切片验证过中止行为。
