# M01_S01.007.FIX — 完整性、迁移与发布门禁收敛

> 日期：2026-09-19。触发：项目质量复核后继续迭代。目标是把“高质量 v0”中仍会
> 让用户得到错误答案、崩溃或误判成功的缺口，收敛到可回归验证的门禁。

## 本轮结论

- CAS 幂等写按 BLAKE3 内容校验；同长度篡改和截断都会在重新发布时自愈，临时文件
  使用唯一名、`create_new`、`sync_all` 和原子 rename。
- 数据目录在 POSIX 上收紧为 `0700`，数据库/WAL/SHM、PID、lock 和 CAS 对象为
  `0600`；数据库打开拒绝符号链接，避免“检查之后再打开”跟随外部路径。
- SQLite 引入 schema version 1。全新库和无版本的 v0 旧库会登记为 version 1；部分、
  不兼容或更高版本的库在启动/请求边界明确失败，不再把缺列变成空响应或 handler panic。
- CLI 的 health 只接受 Pageville 的成功 JSON；`daemon stop` 检查 HTTP 状态并传播错误，
  foreign listener 不再伪装成可控 daemon。
- CI 改为运行完整 `npm test`，增加 RustSec、Dependabot、npm/Node 启动器测试、贡献/安全/
  变更日志与 release provenance/attestation。
